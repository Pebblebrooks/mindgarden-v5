# v5.0.0 — clearer first screen and menus

15 November 2026. Built from v4.0.56. No database schema change.

## What changed for players

- Home shows the game cards on first load, with one large **Start today's games** button. A player who has already chosen to hide the cards in v5 keeps that choice; choices saved before v5 are reset to shown once.
- Top bar: phones show the Mind Garden name and a labelled **Menu** button. Sign in, Language, text size, display mode and garden animation are in the menu. Wide screens keep the main links, Sign in and Language on the bar.
- Language opens a picker (English / 中文) and changes only when one is chosen.
- Help on a home card opens in a centred dialog on touch and narrow screens.
- Today's Games: the first screen is titled "Today's Games · Activity n of 3" and **Begin** starts the activity directly.
- All Games: the page is titled All Games, categories are buttons, and phones show two columns.
- My Games: the panel is titled My Games; the remove (×) control appears only after choosing **Remove games**.
- My Progress: tab labels no longer break mid-word.
- One circular information-button style in dialogs; menu icons match the home cards; the Language menu item shows its icon.
- About (English and Chinese) and the Quick guide describe the new paths.

## Deploying as a new Cloudflare Pages project

1. Create the Pages project from this repository. Production branch `main`, no build command, output directory `public`.
2. Bind D1: variable name `DB`, database `mindgarden-db`.
3. Set `MG_ACCOUNT_PEPPER` to exactly the same value as the existing project. A different value means existing accounts cannot sign in.
4. Set `MG_ACCOUNT_SIGNUP=enabled` if new registrations should be allowed.
5. Redeploy after adding bindings, then check About shows v5.0.0 and that `garden-ui-500.js` loads.
6. A new project has a new site address. Players and progress saved only on a device stay with the old address in that browser; they do not appear at the new one unless the player signs in to an account or restores an exported backup.
7. Device sign-in (passkeys) is tied to the site address, so passkeys registered on the old address will not work on a new one; password sign-in is unaffected.
